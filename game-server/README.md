# joyeondang-game: 함께 걷기 서버

걷기 화면에서 같은 공간(집 또는 방 하나)에 있는 손님들이 서로의 캐릭터·이름표·말풍선을 보게 하는 작은 서버다.
Cloudflare Worker 하나와 Durable Object 클래스 `Space` 하나로 되어 있고, 공간마다 DO가 하나씩 생긴다(`idFromName(space)`).
Next 사이트와는 따로 묶고 따로 배포한다(루트 tsconfig·eslint에서 이 폴더를 뺐다).

| 파일 | 하는 일 |
|---|---|
| `src/index.ts` | 문지기: `GET /connect?space=&token=` WebSocket 업그레이드만. Origin(`ALLOWED_ORIGINS`), 공간 이름(`house:real`, `room:[a-z0-9-]{2,32}`), 출입증을 보고 DO로 넘긴다. `/health`는 `ok` |
| `src/space.ts` | DO. WebSocket Hibernation API(`ctx.acceptWebSocket`, 사람 정보는 `serializeAttachment`). 100명까지(넘치면 다음 공간을 알려 준다), 같은 사람이 다시 들어오면 앞 연결을 닫는다. 관전자는 따로 센다 |
| `src/protocol.ts` | 짧은 키 JSON 규약과 값 검사. 사이트 쪽 짝은 `src/walk/net.ts` |
| `src/token.ts` | 출입증과 사진 겉모습 증표 확인(WebCrypto HMAC-SHA256, 시간 일정 비교). 서명은 사이트 `src/lib/game-token.ts` |
| `test/smoke.mjs` | 로컬 연기 시험(두 손님 흉내, 거절, 속도 제한, 겉모습과 사진 증표, 넘치면 끊기, 101번째 full과 다음 공간, 관전자) |

위치·말은 저장소에 쓰지 않는다. 연결이 끊기면 사라진다.

## 출입증
사이트 `GET /api/game-token`(손님 이상만, 아니면 404)이 `{ token, url, exp }`를 준다.
`token = base64url(JSON {sub, name, color, role, exp}) + '.' + base64url(HMAC-SHA256(GAME_TOKEN_SECRET, 앞부분 글자))`, `exp`는 유닉스 초, 10분.
`sub`는 로그인 id를 서명 키로 한 번 감춘 값이라 이 서버는 실제 계정 id를 모른다. 다른 사람에게는 연결마다 새로 만든 짧은 id만 보인다.

### 사진 겉모습 증표
겉모습 메시지 `{t:'k', look, p?}`의 사진 캐릭터는 그 사람의 그림일 때만 받는다: 출입증에 실려 온 사진과 같거나,
사이트 `GET /api/game-token/look?id=<그림 id>`(자기 그림일 때만 준다)가 서명한 증표 `p`가 맞을 때.
`p = exp + '.' + base64url(HMAC-SHA256(GAME_TOKEN_SECRET, 'look:' + sub + ':' + url + ':' + exp))`, 10분.
붙어 있는 동안 사진 캐릭터를 새로 만들면 출입증에는 옛 겉모습이 실려 있어서 증표가 필요하다.
**배포 순서: 증표를 보내는 사이트를 먼저 배포하고, 그다음 이 서버를 배포한다.** 거꾸로 하면 사이트가 배포될 때까지
방금 만든 사진 캐릭터가 남에게 인형으로 보인다(다시 이으면 출입증의 겉모습으로 보인다).
사이트를 배포하기 전에 열어 둔 창(옛 화면)은 증표를 보내지 않는다: 그 창에서 새로 만든 사진은 새로 고칠 때까지 같은 처지다.
화면은 증표를 못 받으면 3·10·30초 뒤 다시 받아 보고, 받으면 증표를 붙여 겉모습을 다시 보낸다(`src/walk/net.ts`).

## 수용 인원과 다음 공간
한 공간(집 또는 방 하나)에 걷는 사람 100명(`MAX_PLAYERS`). 101번째부터는 `{t:'full', to:'<공간>~2'}`를 받고, 걷기 화면은
가득 찼다는 알림 없이 그 공간으로 바로 들어간다(`house:real` → `house:real~2` → `house:real~3`, `MAX_SHARDS` 3).
다음 공간은 따로 도는 DO라 처음 공간 사람들과 서로 보이지 않는다. 마지막 공간도 차면 그때 `full`(화면은 30초 뒤 다시).
다시 이을 때는 처음 공간부터 두드리므로 자리가 나면 처음 공간으로 돌아온다. 옛 화면은 `to`를 모르고 지금처럼 30초 뒤 다시 두드린다.
알려진 동작: 같은 사람의 앞 연결을 닫는 일은 공간(DO) 하나 안에서만 한다. `~2`에서 걷던 손님의 휴대폰이 닫기 없이 끊긴 뒤
처음 공간으로 다시 들어오면, `~2`의 사람들에게는 그 캐릭터가 멈춘 채 30초(`STALE_MS`)와 정리 주기만큼 남았다가 사라진다.
`~2`에 탭을 둔 채 새 탭을 열면 두 공간에 동시에 있을 수도 있다(둘 다 같은 사람의 걷기라 해는 없다).
**컨트롤 룸처럼 모두를 보려면 공간마다 관전 연결을 하나씩 둔다**(`spaceShards('house:real')` → 세 이름. 빈 공간의 관전 연결은
공간을 깨우지 않는다).

2026-11-11 로컬 측정(로컬 부하 측정 도구, 공개 레포에는 없음. 개발용 맥의 wrangler dev, 다른 작업이 많이 돌던 때라 시간 값은 참고만):

휴대폰 화면(같은 도구의 화면 측정, 390×844, CPU 4배 느리게, 인형 캐릭터): 3인칭으로 사람들을 보면 60명일 때 그리기 호출 616·삼각형 46만·프레임당 JS 11.5ms,
100명일 때 745·62만·14.2ms(p95 17.7ms), 둘 다 60fps 안팎. 1인칭은 559 → 611. 서버는 100명에도 여유가 크고, 늘어나는 것은
휴대폰이 그리는 양(+20%쯤)과 받는 양이다. 사진 3D 캐릭터가 많아지면 걷기 엔진이 가까운 몇 명만 3D로 그려야 한다(걷기 엔진 몫).

## 관전(컨트롤 룸)
사이트 `GET /api/game-token?observe=1`은 가족·관리자에게만 역할 `observer`인 출입증을 준다(그 밖에는 손님이어도 404).
걷기 화면 쪽은 `connectNet({ space, observe: true, onPlayers, onStatus, onChat })`(같은 함수를 `createNet`으로도 부른다).
- 관전자는 사람 수(`MAX_PLAYERS`)에 세지 않는다. 가득 찬 공간에도 들어온다. 공간마다 `MAX_OBSERVERS`(6)개, 같은 사람은
  `OBSERVERS_PER_SUB`(3)개까지다. 자리가 모자라면 90초(`OBSERVER_QUIET_MS`) 넘게 소식이 없는 조용한 연결부터 비우고(`bye replaced`),
  모두 살아 있으면 새 연결을 `full`로 돌려보낸다. 켜 둔 녹화 화면이 새로 연 탭에 밀려나지 않고, 닫기 없이 죽은 연결은 자리를 내준다.
  자리를 내준 관전 화면은 꺼지지 않고 15초 뒤 다시 잇는다(걷는 연결은 `replaced`를 받으면 다른 창을 위해 쉰다).
- 출입증이 끝나고 2분(`OBSERVER_EXP_GRACE_MS`)이 지난 관전 연결은 ping에 답해도 정리한다. 화면은 새 출입증을 받아 다시 이으며,
  그때 사이트가 역할(가족·관리자)을 다시 확인한다. 가족에서 빠진 계정이 계속 지켜보지 않게.
- 남의 `hi` 목록·`j`·`l`에 나오지 않는다. 받는 소식은 걷는 사람과 같다(`hi`(`o: 1`이 붙는다), `j`, `S`, `c`, `k`, `l`).
- 상태·말·겉모습을 보내도 버린다. 같은 사람이 한 창에서 걸으면서 다른 창에서 관전해도 서로 닫지 않는다.
- 살아 있는지: 화면은 5초마다 글자 `ping`을 보내고, 런타임이 공간을 깨우지 않고 `pong`으로 답한다
  (`setWebSocketAutoResponse`). 답이 10초 넘게 없으면 화면이 끊고 다시 잇는다. 서버는 받은 메시지와 ping 답한 때를 함께 보아
  3분(`OBSERVER_STALE_MS`) 소식이 없는 관전 연결을 정리한다. 사람이 없는 집을 밤새 관전해도 공간은 잠들 수 있다.
- 관전 연결은 탭이 숨어도 끊지 않는다(뒤에 띄워 둔 컨트롤 룸이 기록을 이어 가게). 페이지를 떠날 때만 끊는다.
- 아무것도 보내지 않은 연결은 서버가 닫아도 닫기 프레임이 늦게 끝날 수 있다. 그래서 서버는 닫기 전에 `bye`로 까닭을 말하고,
  화면은 `bye`를 받으면 스스로 닫는다.

## 로컬에서 띄우기
```bash
cd game-server
npm install
npx tsc --noEmit
npx wrangler dev --port 8788      # 로그인 없이 로컬로만 돈다
```
`.dev.vars`(커밋 안 함, `.gitignore`에 있음)에 시험값을 둔다.
```
GAME_TOKEN_SECRET=<아무 긴 시험 문자열, 32자 이상 권장>
ALLOWED_ORIGINS=http://localhost:3331,http://127.0.0.1:3331,http://localhost:3334,http://127.0.0.1:3100
```
이 맥은 8787 포트를 다른 로컬 서비스가 쓰고 있어 8788 이후를 쓴다.

연기 시험(비밀값은 환경 변수로만 넘기고 화면에 찍지 않는다):
```bash
set -a; . ./.dev.vars; set +a
SMOKE_URL=http://127.0.0.1:8788 node test/smoke.mjs
```
사이트와 같이 보려면 Next에 `GAME_SERVER_URL=ws://127.0.0.1:8788`, `GAME_TOKEN_SECRET=<.dev.vars와 같은 값>`, `JY_LOCAL_PREVIEW=1`을 준다(Next는 `-H 127.0.0.1`로 이 컴퓨터에만 묶어 띄운다: `npm run preview:local`. 그 주소 `http://127.0.0.1:3100`이 위 `ALLOWED_ORIGINS`에 있어야 이어진다).
로컬 미리보기에서는 창마다 다른 손님으로 출입증이 나온다.

## 배포(사람이 한 번)
1. `npx wrangler login` (Cloudflare 계정. 사람이 많이 모이는 날이 있으면 Workers Paid. 아래 비용 메모)
   셸에 `CLOUDFLARE_API_TOKEN`이 잡혀 있으면 wrangler가 로그인 대신 그 토큰을 쓴다. 그 토큰에 Workers 권한이 없으면
   「계정을 찾지 못했다」가 나오니 `env -u CLOUDFLARE_API_TOKEN npx wrangler …`로 로그인한 계정을 쓴다
2. `npx wrangler deploy` → 주소가 `https://joyeondang-game.<계정 하위 도메인>.workers.dev`로 나온다
3. `npx wrangler secret put GAME_TOKEN_SECRET` (긴 무작위 값, 예: `openssl rand -base64 48`)
4. 걷기 화면 주소가 바뀌면 `wrangler.jsonc`의 `ALLOWED_ORIGINS`를 고치고 다시 배포
5. Vercel 환경 변수: `GAME_SERVER_URL=wss://joyeondang-game.<계정 하위 도메인>.workers.dev`, `GAME_TOKEN_SECRET=<3과 같은 값>`(Production에만)
6. 확인: `curl https://…workers.dev/health` → `ok`, 두 브라우저로 손님 로그인 뒤 서로 보이는지

`migrations`의 `v1`(`new_sqlite_classes: ["Space"]`)은 이미 배포한 뒤에는 고치지 않는다. 클래스를 바꾸면 새 태그를 더한다.
로그(observability)는 꺼 두었다. 요청 주소에 출입증이 들어 있어서다. 켜야 하면 짧게 켜고 끈다.

## 비용 메모(2026-11 기준, Cloudflare 문서)
- 요금제: **Workers Paid**(이 계정은 2026-11-11부터). 월 최소 5달러에 Durable Objects 요청 월 100만(넘으면 100만당 0.15달러),
  시간 월 40만 GB-s(넘으면 100만 GB-s당 12.5달러), SQLite 저장소 5GB가 들어 있다(Workers 요청·CPU도 넉넉히 들어 있다). 하루 한도는 없다.
- DO는 SQLite 백엔드(`new_sqlite_classes`)라 무료·유료 어느 요금제에서도 돈다.
- 요청 세는 법: WebSocket 연결 1번 = 1요청, 받은 메시지는 20개 = 1요청, 보내는 메시지와 들어오는 ping은 무료.
  걷기 화면이 보내는 빈도: 걸으면 0.15초마다(시간당 약 1,200요청), 서서 둘러보기만 하면 0.4초마다(약 450요청),
  가만히 있으면 3초마다(60요청). 손님 10명이 하루 2시간씩 계속 걸어도 약 24,000요청.
- 행사 규모로 보면: 50명이 함께 있고 그 가운데 3할이 걷고 나머지가 둘러보면 시간당 약 3만 요청, 100명이면 시간당 약 5.6만
  (모두 걸으면 12만) 요청이다(위 측정). 세 시간짜리 행사도 수십만이라 Paid의 월 포함량(100만) 안이다.
- 무료 요금제로 내리면 하루 100,000 요청이라 사람이 많이 모이는 날은 모자란다(50명이면 서너 시간, 100명이면 한두 시간에 찬다).
  요금제를 올리고 내리는 것은 Cloudflare 계정의 Workers 요금제 화면에서 한다(그때의 금액은 Cloudflare 문서로 확인한다).
- 너무 많이 보내는 연결은 서버가 끊는다. 한꺼번에 100개까지 받고 초당 30개씩 다시 차는 통으로 센다
  (`FLOOD_BURST`, `FLOOD_PER_SEC`). 버리기만 하면 받을 때마다 서버가 깨어나, 고장 난 화면 하나가 하루 한도를 다 쓸 수 있어서다.
  통신이 몇 초 막혔다 풀려 한꺼번에 몰려 온 정상 메시지는 통이 받아 준다. 끊긴 사람은 20초 동안 다시 들이지 않고(`FLOOD_REST_MS`),
  걷기 화면은 스스로 30초(거듭되면 두 배, 5분까지) 쉬었다 다시 잇는다. 걷기 화면은 보낸 것의 답이 1초 넘게 없으면
  1초에 한 번만 보내, 막힌 동안 쌓아 두지 않는다.
  100명 기준으로 다시 봤다(2026-11-11): 통은 연결마다 세므로 사람 수와 상관없다(보통 화면은 초당 7개 안팎). 모두가 끊기기 직전
  빠르기(초당 30개)로 보내는 최악의 경우도 초당 3,000개로, 측정한 처리량(초당 669개에 한 코어 4%)으로 보면 공간이 감당한다. 그대로 둔다.
- 시간: DO 하나를 128MB로 센다. 사람이 있는 동안 3초마다 상태가 와서 DO가 깨어 있으므로, 사람이 있는 공간 하나가
  한 시간 깨어 있으면 약 450 GB-s다. Paid의 월 40만 GB-s에 비하면 작다(무료 요금제는 하루 13,000 GB-s).
- 무료 요금제에서 하루 한도를 넘으면 그날(UTC 0시까지) 연결이 실패하고, 걷기 화면은 혼자 걷기로 돌아간다(오류 없이).
- 저장소는 거의 쓰지 않는다(위치·말을 저장하지 않음).
